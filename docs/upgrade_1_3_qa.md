# BankGuard 1.3 — изменения и проверка

Основная платформа: ПК. Тёмное рабочее место с очередью слева и карточкой справа.

## Реализованы все семь направлений

1. Тёмная графитовая тема: приглушённый зелёный, более читаемые поля, заметные состояния фокуса.
2. Очередь ожидающих решения по умолчанию; «На проверке», «Обработанные», «Все» со счётчиками. Пагинация остаётся по 20 операций.
3. Карточка: статус, сумма, риск, причины, комментарий, решение; исходные поля и вопросы раскрываются отдельно.
4. Сохранение выбранного решения и переход к следующей тревоге, подтверждение и сообщение о завершении очереди.
5. Автосохранение решений, корректных настроек и черновиков в localStorage. Явное восстановление после перезагрузки, выключение, подтверждаемая очистка. Проверка формата, лимитов, идентификаторов и конфликтов между вкладками. Некорректные числовые поля не заменяют последние корректные настройки.
6. График порогов 1–100: проверки, ложные тревоги и пропуски, маркер выбранного порога, разные штрихи линий, текстовая альтернатива и таблица точных значений.
7. Playwright: шесть сценариев на двух размерах окна ПК (1440×1000 и 1280×800), npm-команда, lockfile, отдельное задание GitHub Actions с отчётом.

## Подтверждено

- 100 модульных тестов проходят, сборка проходит, CLI воспроизводит 9 экспериментов.
- Во встроенном Chromium: обязательный комментарий; сохранение с переходом дальше для эскалации и снятия с проверки; последовательная обработка всех шести тревог; счётчики и состояние пустой очереди.
- Черновик и решение восстанавливаются после перезагрузки; нулевая ёмкость и порог 100 восстанавливаются без подмены значений.
- Удаление локальной копии выключает автосохранение и сохраняет текущую работу в открытой вкладке. Новая вкладка после удаления запускается без предложения восстановления.
- Набор 1000: 127 ожидающих при пороге 50; страницы 1–20 и 21–40, поиск без результатов, возврат к сюжетному набору.
- График: при пороге 1 значения 13/6/0, при 100 — 0/0/7 (проверки/ложные тревоги/пропуски).
- Скачаны пять видов файлов: операции CSV, пакет кейса, эксперимент, журнал и демо-сессия.
- Дополнительная проверка узкого CSS-макета через iframe не обнаружила горизонтального переполнения body в четырёх разделах. Это дополнительная совместимость, а не основная платформа или эмуляция телефона.

## Ограничения

Отдельный Chromium для Playwright завершился до выполнения тестовых действий: `socket() failed: Operation not permitted`. Поэтому 12 автоматических браузерных прогонов не объявляются прошедшими. Они подготовлены для локального запуска и CI. Статус удалённого CI следует проверять во вкладке Actions репозитория; локальная проверка не подтверждает его результат.

Автосохранение не является банковским хранилищем: только вымышленные данные, локальный браузер, без шифрования и серверной авторизации. JSON-экспорт остаётся совместимым с прежним форматом и не включает черновики. Неполные параметры лаборатории восстанавливаются в последнем корректном состоянии. При недоступном хранилище интерфейс сообщает об ошибке и предлагает сохранить файл.

## Проверка на ПК

```sh
npm test
npm run build
npm run demo:verify
npm ci
npx playwright install chromium
npm run test:e2e
```

Для обычного запуска достаточно Node.js 20+ и `npm start`; зависимости нужны только для браузерных тестов.
